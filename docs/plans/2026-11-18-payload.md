# Payload Implementation Plan

> **For the people doing this:** Stages 1 and 2 are bench work and a decision. Tasks 3 and 4 are code, for agentic workers using superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Needs the project lead's decision at the end of Stage 2:** the grabber is hardware beyond the loan kit (`AGENTS.md`, Stop and Ask). Task 3 is flight controller code and needs the same OK.

**Goal:** Carry the 50 g disc under the drone, hold it through a flight and a window crossing, and release it so that its first contact with the ground is on an A3 poster. Each drop is 20 points, and the drop completes a full mission worth 100.

**Approach:** Test before choosing. The rules' disc has a Ø40 mm ferrous plate, and two Namvo KK-P20 electromagnets are recorded in the box, so the electromagnet is the candidate to beat: no moving parts and an instant release. The drop test gives the height to drop from and the hit rate to expect. Only then is the driver written.

**Sources:** `docs/contest-rules.md` (Objects, Part 1); `droneload/payload/README.md`. Electrical values below are typical for this magnet and **unverified until measured**.

## Global Constraints

- The disc: circular, 50 g at most, Ø40 mm ferrous plate, Ø62 mm ring. Make three test discs to that description; the team may bring its own to the final, checked at qualification.
- A hit means the first ground contact is on the poster. A disc that lands off it and rolls on does not count.
- The grabber counts toward the 3 kg limit and must not hang below the landing gear.
- The magnet is powered to hold. **If power fails, the disc falls.** That is acceptable over the arena; never fly it over people.
- A magnet is an inductive load: it needs a flyback diode, and the flight controller's pin must drive a switch (a logic-level MOSFET module), never the magnet itself.
- Keep the magnet at least 10 cm from the compass, and measure the compass with the magnet on and off (Stage 1).
- Branch `feature/payload`, log `logs/YYYY-MM-DD-feature-payload.md`.

### Stage 1: Bench test of the electromagnet

- [ ] Confirm the two KK-P20 magnets are in the box. Read their rated voltage and measure their current. If they are 12 V parts, the 3S battery (9.9 to 12.6 V) can feed them through the switch.
- [ ] Hold test: with the lowest battery voltage the failsafe allows, hang a test disc and add mass until it falls. The margin wanted is 5 times the disc's weight, so 250 g.
- [ ] Shake test: hold the powered magnet and disc in the hand and shake hard for 30 s, in every direction. The disc must stay.
- [ ] Release test: film the release at 240 fps on a phone. Note the delay between switching off and the disc leaving, and whether the disc ever sticks.
- [ ] Heat test: leave the magnet on for 15 minutes, the length of a run, and note its temperature and current.
- [ ] Compass test: with the magnet mounted where it would fly, note the flight controller's heading with the magnet off and on. A change of more than 5° means moving it or shielding it.

**Pass:** holds 250 g, survives the shake, releases within 0.2 s every time in 20 tries, and moves the compass by under 5°.

### Stage 2: Drop accuracy, and the decision

- [ ] Fix the magnet to a stand or a pole. Drop 20 times each from 0.5, 1.0 and 1.5 m onto an A3 sheet on the floor type the organisers announce, or on concrete and on a tarp if they have not.
- [ ] For each drop record where the disc first touched and where it stopped. Count first-contact hits.
- [ ] Repeat the best height with the stand swinging about 10 cm, to stand in for a hovering drone.
- [ ] Write the table in `droneload/payload/README.md`, with the chosen drop height and the hit rate target.
- [ ] **Decision for the project lead:** electromagnet, or a servo claw on the Ø62 mm ring if the magnet failed Stage 1 or 2. Record it in `logs/DECISIONS.md`.

**Pass:** a drop height with at least 18 hits in 20 with the stand still. If no height reaches that, the centring tolerance in `navigation` must tighten or the height must drop; say which in the README.

### Task 3: Relay output in `flight`

Assumes the electromagnet, switched by a flight controller relay pin. If Stage 2 chose a servo, replace `set_relay` with `set_servo` (`MAV_CMD_DO_SET_SERVO`) and keep the rest.

**Files:**
- Modify: `droneload/flight/vehicle.py`, `testing/fake_vehicle.py`, `testing/sitl_sensors.parm` (a simulated relay pin)
- Create: `droneload/flight/stabilisation/grabber.parm` (the relay's `RELAY1_FUNCTION = 1`, `RELAY1_PIN` and `RELAY1_DEFAULT = 0`, once the pin is chosen on the kit)
- Test: `tests/test_flight.py`, `tests/test_flight_sitl.py`

**Interfaces:**
- Produces: `vehicle.set_relay(index, on) -> None`, which sends `MAV_CMD_DO_SET_RELAY` with the relay's number (0 for the first relay) and 1 or 0. `KinematicVehicle` gains the same method and a `relays` dict.

- [ ] **Step 1: Write the failing tests.** `test_set_relay_sends_the_command` (number 0, value 1), `test_relay_rejected_raises` (a denied ack raises `CommandRejected`), and the opt-in simulator test `test_relay_is_accepted_in_guided` (the command is acknowledged as accepted while flying in Guided).
- [ ] **Step 2: Run them and check they fail.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run the unit and simulator tests.** If the simulator rejects the command in Guided, stop and record it: the fallback is a GPIO on the companion computer, which depends on the board.
- [ ] **Step 5: Commit.** Message "Add a relay output for the grabber".

**Files:**

- Modify: `droneload/mission/plans.py`
- Test: `tests/test_payload.py`

**Interfaces:**
- Consumes: `Vehicle.set_relay`, `Context`.
- Produces:

```python
RELAY_INDEX    = 0
RELEASE_WAIT_S = 0.5      # from Stage 1's release delay, with margin
DROP_HEIGHT_M  = 1.0      # from Stage 2

class Grabber:
    def __init__(self, vehicle): ...
    holding: bool
    def grab(self) -> None        # relay on
    def release(self) -> None     # relay off

class Grab:                        # a step: relay on, then WaitConfirm, since the disc is fitted by hand
class Drop:                        # a step: stop, release, wait RELEASE_WAIT_S, done
    def __init__(self, timeout_s=10): ...
```

`Drop` fails without releasing if the drone's horizontal speed is above 0.1 m/s. The plan before take-off starts with `Grab()`, so the magnet is on before the disc is offered.

- [ ] **Step 2: Run them and check they fail.**
